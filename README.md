# نوآفر — پلتفرم نوآوری اجتماعی

اپلیکیشن تک‌صفحه‌ای React به همراه یک API روی Node.js و PostgreSQL.
سرور، هم API را سرو می‌کند و هم فایل‌های ساخته‌شدهٔ فرانت‌اند را، بنابراین
برای دیپلوی فقط به **یک سرویس** و **یک پایگاه‌دادهٔ PostgreSQL** نیاز دارید.

## ساختار پروژه

```
src/            رابط کاربری React (Vite + TypeScript + Tailwind v4)
  services/     لایهٔ ارتباط با API و احراز هویت
  mocks/        محتوای نمونهٔ اولیه — فقط برای seed کردن پایگاه‌داده
server/src/     سرویس API
  schema.sql    ساختار پایگاه‌داده (idempotent، در هر بوت اجرا می‌شود)
  routes/       مسیرهای API
  lib/          احراز هویت، پاک‌سازی HTML، محدودیت نرخ، امتیازها
scripts/        اسکریپت ساخت سرور
```

## اجرای محلی

```bash
npm install
cp .env.example .env          # سپس DATABASE_URL و SESSION_SECRET را پر کنید
npm run build                 # ساخت فرانت‌اند و سرور
npm run db:seed               # بارگذاری محتوای نمونه (یک‌بار، اختیاری)
npm start                     # http://localhost:4000
```

برای توسعه با hot-reload، در دو ترمینال جدا:

```bash
npm run dev:server            # API روی پورت ۴۰۰۰
npm run dev                   # فرانت‌اند روی پورت ۳۰۰۰
```

## دیپلوی روی Runflare

۱. یک پایگاه‌دادهٔ **PostgreSQL** بسازید و رشتهٔ اتصال آن را بردارید.

۲. سرویس Node.js را با این تنظیمات بسازید:

| مورد | مقدار |
| --- | --- |
| Build command | `npm install && npm run build` |
| Start command | `npm start` |
| Node version | ۲۰ یا بالاتر |
| Port | همان مقدار `PORT` (پیش‌فرض ۴۰۰۰) |

اگر ترجیح می‌دهید از ایمیج استفاده کنید، `Dockerfile` موجود در ریشهٔ پروژه
همین کار را انجام می‌دهد.

۳. متغیرهای محیطی را از روی `.env.example` تنظیم کنید. حداقل موارد لازم:

```
NODE_ENV=production
DATABASE_URL=postgresql://...
DATABASE_SSL=true
SESSION_SECRET=<رشتهٔ تصادفی ۶۴ کاراکتری>
TRUST_PROXY=true
BOOTSTRAP_ADMIN_PHONES=09xxxxxxxxx     # شمارهٔ خودتان، فقط برای اولین ورود
```

تولید کلید نشست:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

۴. یک **volume** روی مسیر `UPLOAD_DIR` (پیش‌فرض `./uploads`) وصل کنید تا
فایل‌های بارگذاری‌شده با هر دیپلوی پاک نشوند.

۵. جدول‌ها در اولین بوت خودکار ساخته می‌شوند. برای بارگذاری محتوای نمونه
یک‌بار `npm run db:seed` را روی سرور اجرا کنید (یا `SEED_ON_BOOT=true`
بگذارید؛ این گزینه فقط وقتی پایگاه‌داده خالی است کار می‌کند).

## دیپلوی روی Vercel (به همراه Neon)

سرویس روی Vercel به‌صورت **Serverless Function** اجرا می‌شود: فایل
`api/[...path].ts` همان اپلیکیشن Express را صادر می‌کند و `vercel.json`
مسیردهی را انجام می‌دهد. فایل‌های فرانت‌اند مستقیم توسط Vercel سرو می‌شوند.

۱. پایگاه‌داده را روی Neon بسازید و **رشتهٔ اتصال Pooled** را بردارید
   (نشانی‌ای که در آن `-pooler` دیده می‌شود). در معماری بدون‌سرور هر نمونه
   اتصال جداگانه باز می‌کند و بدون Pooler سقف اتصال‌های Neon سریع پر می‌شود.

۲. در Vercel → Settings → Environment Variables این‌ها را وارد کنید:

```
DATABASE_URL=postgresql://...-pooler.../neondb?sslmode=require
DATABASE_SSL=true
SESSION_SECRET=<رشتهٔ تصادفی ۶۴ کاراکتری>
PUBLIC_URL=https://<your-domain>
BOOTSTRAP_ADMIN_EMAILS=<you@example.com>
```

`NODE_ENV` را Vercel خودش روی `production` می‌گذارد. `PORT`، `HOST`،
`PUBLIC_DIR` و `TRUST_PROXY` لازم نیستند.

۳. دیپلوی کنید. جدول‌ها در اولین درخواست ساخته می‌شوند (با قفل مشورتی
   پایگاه‌داده، تا چند نمونهٔ هم‌زمان با هم تداخل نکنند).

۴. برای بارگذاری محتوای نمونه، یک‌بار روی رایانهٔ خودتان:

```bash
DATABASE_URL='<همان رشتهٔ اتصال>' npm run build:server && npm run db:seed
```

### عیب‌یابی

نشانی `‎/api/health` وضعیت سرویس را می‌گوید و اولین جایی است که باید ببینید:

| پاسخ | معنی |
| --- | --- |
| `{"ok":true,...}` | سرویس و پایگاه‌داده سالم‌اند. |
| `404` یا صفحهٔ HTML | تابع بدون‌سرور اصلاً مستقر نشده است. مطمئن شوید شاخه‌ای که Vercel می‌سازد، پوشهٔ `api/` و فایل `vercel.json` را دارد. |
| `503` با `code: "config_error"` | متغیر محیطی کم است؛ نام‌ها در فهرست `problems` می‌آید. |
| `503` با `code: "database_unavailable"` | `DATABASE_URL` یا `DATABASE_SSL` درست نیست؛ پیام می‌گوید کدام. |

اگر هنگام ورود پیام «سرویس API در دسترس نیست» دیدید، یعنی درخواست اصلاً به
تابع نرسیده و همان حالت دوم جدول بالاست.

### محدودیت مهم: بارگذاری فایل

سیستم‌فایل روی Vercel موقتی است و بین درخواست‌ها پاک می‌شود. برای همین
بارگذاری فایل (آواتار، تصویر محتوا، ویدیوی درس) روی Vercel **عمداً غیرفعال**
است و پیام روشنی برمی‌گرداند — تا فایل‌ها بی‌صدا از بین نروند. در این حالت
می‌توانید نشانی اینترنتی تصویر را مستقیم وارد کنید.

برای فعال‌کردن بارگذاری، یا روی میزبانی با دیسک پایدار (مثل Runflare با
volume) دیپلوی کنید و `UPLOADS_PERSISTENT=true` بگذارید، یا فضای ذخیره‌سازی
ابری (Vercel Blob، S3 و مانند آن) اضافه کنید.

## ساخت اولین مدیر

نقش مدیر فقط در پایگاه‌داده تعیین می‌شود؛ هیچ رمز عبوری در سمت مرورگر وجود
ندارد.

* **راه اول (توصیه‌شده):** شناسهٔ خود را در متغیر محیطی بگذارید، یک‌بار وارد
  شوید، سپس مقدار آن را خالی کنید:

  ```
  BOOTSTRAP_ADMIN_EMAILS=you@example.com     # ورود با رایانامه و گذرواژه
  BOOTSTRAP_ADMIN_PHONES=09xxxxxxxxx          # ورود با کد پیامکی
  ```

  اگر حساب از قبل ساخته شده باشد، در همان ورودِ بعدی به `admin` ارتقا می‌یابد.

* **راه دوم:** مستقیم در پایگاه‌داده (بدون نیاز به ری‌استارت سرویس):

  ```sql
  UPDATE users SET role = 'admin' WHERE lower(email) = 'you@example.com';
  -- یا
  UPDATE users SET role = 'admin' WHERE phone = '09xxxxxxxxx';
  ```

  پس از تغییر نقش، یک‌بار خارج و دوباره وارد شوید (تغییر نقش نشست‌های قبلی را
  باطل می‌کند).

نقش‌های موجود: `member` (پیش‌فرض)، `operator` (داوری محتوا و دیدگاه‌ها) و
`admin` (دسترسی کامل، شامل تغییر نقش کاربران).

## ورود کاربران (کد یک‌بارمصرف)

ورود با شمارهٔ موبایل و کد پنج‌رقمی انجام می‌شود. کد به‌صورت hash‌شده
(scrypt) ذخیره می‌شود، دو دقیقه اعتبار دارد، فقط یک‌بار قابل استفاده است و
در برابر حدس زدن با محدودیت نرخ به‌ازای شماره و IP محافظت می‌شود.

بدون تنظیم سرویس پیامک (`SMS_PROVIDER=console`) کد در **لاگ سرور** چاپ
می‌شود؛ برای راه‌اندازی واقعی یکی از این‌ها را تنظیم کنید:

```
SMS_PROVIDER=kavenegar
SMS_API_KEY=<api key>
SMS_TEMPLATE=<نام الگوی verify>      # اختیاری ولی برای تحویل بهتر توصیه می‌شود
```

```
SMS_PROVIDER=smsir
SMS_API_KEY=<api key>
SMS_TEMPLATE=<template id عددی>
```

## ورود با رایانامه و گذرواژه

علاوه بر کد یک‌بارمصرف پیامکی، کاربران می‌توانند با رایانامه و گذرواژه ثبت‌نام
کنند و وارد شوند. هر حساب می‌تواند هر دو راه را داشته باشد: کاربری که با
شماره موبایل وارد شده، از «میز کار ← ویرایش پروفایل» می‌تواند رایانامه و
گذرواژه هم برای حساب خود تعیین کند.

نکات پیاده‌سازی:

* گذرواژه با **scrypt** (پارامترهای حافظه‌سنگین) هش می‌شود و هرگز به‌صورت
  خام ذخیره نمی‌شود.
* پاسخ ورودِ ناموفق برای «رایانامهٔ ناموجود» و «گذرواژهٔ اشتباه» دقیقاً یکسان
  است، تا نتوان با آزمون‌وخطا فهمید کدام نشانی حساب دارد.
* محدودیت نرخ هم روی IP و هم روی خود نشانی اعمال می‌شود.
* با تغییر یا بازیابی گذرواژه، تمام نشست‌های دیگر باطل می‌شوند.

### بازیابی گذرواژه

پیوند بازیابی به رایانامهٔ کاربر فرستاده می‌شود، یک‌بارمصرف است و پس از
`PASSWORD_RESET_TTL_MINUTES` دقیقه منقضی می‌گردد. توکن به‌صورت هش‌شده در
پایگاه‌داده نگهداری می‌شود.

اگر `SMTP_HOST` تنظیم نشده باشد، متن رایانامه در **لاگ سرور** چاپ می‌شود
(همان الگوی پیامک). برای راه‌اندازی واقعی:

```
PUBLIC_URL=https://noafar.ir
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=<username>
SMTP_PASSWORD=<password>
MAIL_FROM=noafar <no-reply@noafar.ir>
```

## پشتیبان‌گیری

داده‌ها در PostgreSQL هستند، پس پشتیبان‌گیری استاندارد است:

```bash
pg_dump "$DATABASE_URL" -Fc -f noafar-$(date +%F).dump
pg_restore -d "$DATABASE_URL" --clean noafar-2026-01-01.dump
```

پنل مدیریت هم یک خروجی JSON از محتوا و ارسال‌ها می‌دهد، اما مرجع اصلی
پشتیبان‌گیری همان `pg_dump` است.
